# Markdown natif dans Google Docs : ce que ça change pour vos flux IA

*Le Levier IA · 6 octobre 2026 · 5 min de lecture*

Google Docs accueille désormais les fichiers Markdown sans conversion — une avancée directe pour les équipes qui manipulent des sorties IA. Deux nouvelles ressources permettent d'évaluer et de déployer des modèles, et les premières alertes sérieuses sur les agents autonomes mal encadrés se précisent.

## L'actualité majeure

### Google Docs édite les fichiers Markdown nativement

*Statut : accessible · annoncé le 5 octobre 2026*

**Ce qui change.** Il est désormais possible d'ouvrir, d'éditer et de collaborer sur des fichiers .md ou .markdown directement dans Google Docs, sans les importer ni les convertir. Google Drive affiche en parallèle un aperçu rendu du fichier. Auparavant, la conversion altérait le formatage, supprimait les commentaires et fragmentait les fichiers.

**Pourquoi c'est important.** Les outils IA génèrent massivement du Markdown pour préserver tableaux, titres et listes. Une agence ou un indépendant peut désormais recevoir un livrable IA en .md, l'ouvrir dans Drive, le faire annoter en équipe dans Docs, puis le livrer au client — sans passer par une étape de conversion qui cassait la mise en forme.

**Limites.** Déploiement progressif : la fonctionnalité peut prendre jusqu'à 15 jours avant d'être visible pour tous les utilisateurs. Disponible pour les domaines Rapid Release et Scheduled Release de Google Workspace. La source ne précise pas les plans concernés ni si tous les comptes au Canada y ont accès.

Sources : [Google Workspace Updates](http://workspaceupdates.googleblog.com/2026/10/preview-edit-and-collaborate-on-Markdown-files-natively-across-Drive-and-Docs.html)

## Nouveautés

### GLM 5.3 de Z.ai disponible sur Amazon Bedrock

*Statut : accès limité · annoncé le 5 octobre 2026*

**Ce que c'est.** GLM 5.3 est un modèle mixture-of-experts de 753 milliards de paramètres, conçu pour le code et les tâches agentiques longues. Il est accessible sur Amazon Bedrock via une API compatible OpenAI, sans avoir à gérer l'infrastructure d'inférence. La prise en charge du prompt caching permet de réduire les coûts sur les appels répétés.

**Pour quoi faire.** Une agence de développement peut appeler GLM 5.3 pour automatiser la revue de code sur de grands dépôts ou pour alimenter des agents qui doivent maintenir un contexte long sur plusieurs heures de traitement.

**Prix.** non précisé par la source

**Limites.** Réservé aux clients entreprise éligibles sur Amazon Bedrock — non disponible pour les comptes individuels sans accord préalable. Les gains de performance annoncés sur les benchmarks de code sont des affirmations de Z.ai (Zhipu AI), non vérifiées de manière indépendante. Le Canada n'est pas mentionné spécifiquement.

Sources : [AWS — Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/introducing-glm-5-3-on-amazon-bedrock/)

### GitHub scanne maintenant les clés Lovable, Pydantic et Supabase

*Statut : accessible · annoncé le 5 octobre 2026*

**Ce que c'est.** GitHub étend son programme de détection de secrets pour couvrir les clés d'API de Lovable Labs, Pydantic Services et Supabase. Lorsqu'une clé est détectée dans un dépôt public, GitHub la transmet au fournisseur concerné pour révocation immédiate.

**Pour quoi faire.** Les agences et développeurs qui utilisent Lovable (création no-code d'applications) ou Supabase (base de données) sont protégés automatiquement si une clé est accidentellement incluse dans un commit public. Aucune configuration requise de leur côté.

**Prix.** inclus dans les plans existants de GitHub (la source ne précise pas de surcoût)

**Limites.** La source décrit la protection pour les dépôts publics uniquement. Elle ne précise pas les conditions pour les dépôts privés. La couverture géographique n'est pas mentionnée.

Sources : [GitHub — Changelog](https://github.blog/changelog/2026-10-05-secret-scanning-adds-detectors-for-lovable-supabase-and-more)

### ReviewBench : un benchmark ouvert pour comparer les outils de revue de code IA

*Statut : accessible · annoncé le 5 octobre 2026*

**Ce que c'est.** GitHub publie ReviewBench, un benchmark de revue de code constitué de 219 pull requests publiques réparties sur 19 langages de programmation, dont la distribution a été calquée sur l'analyse de plus de 100 millions de PR réelles sur GitHub. Il mesure la précision et le rappel d'un agent de revue de code selon un barème standardisé.

**Pour quoi faire.** Une agence de développement peut s'appuyer sur ReviewBench pour comparer objectivement des outils de revue de code automatisée avant d'en adopter un, plutôt que de se fier aux seuls arguments commerciaux des fournisseurs.

**Prix.** non précisé par la source

**Limites.** Le benchmark porte sur des dépôts open source publics sous licence. Les 219 PR peuvent constituer un échantillon limité pour certains langages ou types de projets spécifiques. La source ne précise pas si le Canada est inclus dans le périmètre.

Sources : [GitHub — Blog](https://github.blog/ai-and-ml/github-copilot/reviewbench-an-open-benchmark-for-ai-code-review/)

## Cas d'usage

### Automatiser un flux de production de contenu IA avec n8n

**Le problème.** Une agence coordonne manuellement plusieurs outils IA — génération de texte, résumé, traduction — et multiplie les allers-retours entre ces outils et ses clients, ce qui ralentit la livraison et expose aux erreurs.

**La démarche.** 1. Mettre à jour n8n vers la version 2.43.0. 2. Créer des clés d'API à portée restreinte par client ou par projet grâce à la nouvelle option de gestion des variables (les membres globaux peuvent désormais accorder des portées précises aux clés). 3. Construire un workflow déclenché à la réception d'un brief (e-mail, formulaire, webhook) qui appelle un agent IA, génère le contenu et l'envoie automatiquement dans l'outil de destination (Google Docs, CRM, Slack). 4. Pour les équipes sur Azure, activer le nœud Azure OpenAI Chat mis à jour pour les déploiements en mode Responses-only.

**Les outils.** n8n 2.43.0 (C1)

**L'effort.** Quelques heures pour un workflow de base à un seul outil IA ; davantage pour des chaînes multi-agents. Pas de compétences en code requises pour les cas simples via l'interface visuelle.

**Le résultat attendu.** Les briefs entrants déclenchent automatiquement la chaîne IA jusqu'à la livraison, ce qui réduit les interventions manuelles entre outils et uniformise le traitement des demandes.

**Limites.** La version 2.43.0 est une mise à jour de maintenance aux améliorations incrémentales. L'hébergement en cloud managé (n8n.cloud) ou auto-hébergé influe sur la configuration des clés d'API. La source ne précise pas si toutes les fonctionnalités sont disponibles sur tous les plans.

Sources : [n8n — Releases GitHub](https://github.com/n8n-io/n8n/releases/tag/n8n%402.43.0)
