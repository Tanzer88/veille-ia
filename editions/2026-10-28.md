# GPT-6.1 Terra dans Copilot, n8n 3.0 en bêta : semaine chargée

*Le Levier IA · 28 octobre 2026 · 5 min de lecture*

GPT-6.1 Terra est disponible dans GitHub Copilot comme option moins coûteuse que Sol pour le code agentique au quotidien. n8n publie sa bêta 3.0 avec des breaking changes à anticiper avant la version stable de décembre. Salesforce, de son côté, ajoute un coupe-circuit et un tableau de bord de coûts à Agent Fabric.

## L'actualité majeure

### GPT-6.1 Terra disponible dans GitHub Copilot

*Statut : accessible · annoncé le 26 octobre 2026*

**Ce qui change.** GPT-6.1 Terra, le dernier modèle d'OpenAI, est désormais disponible dans GitHub Copilot. Conçu pour les tâches de code agentique et le travail en terminal, il est proposé à un coût inférieur à GPT-6.1 Sol. Selon GitHub, il surpasse GPT-5.6 Terra sur les tâches de terminal et le code C# dans les tests préliminaires. Les administrateurs des plans Business et Enterprise peuvent en contrôler l'accès via la politique de modèles dans les paramètres Copilot.

**Pourquoi c'est important.** Pour les agences et équipes de développement qui utilisent GitHub Copilot, ce modèle offre une option moins coûteuse que Sol pour les automatisations et les tâches de code courantes. Il s'intègre directement dans les flux de travail existants sans changement de configuration côté utilisateur.

**Limites.** Disponible sur les plans Copilot Pro, Pro+, Max, Business et Enterprise. Les performances annoncées sont issues de tests préliminaires d'OpenAI, non d'évaluations indépendantes. Les tarifs exacts et la disponibilité par région ne sont pas précisés dans les sources.

Sources : [OpenAI — News](https://openai.com/index/introducing-gpt-6-1-terra) · [GitHub — Changelog](https://github.blog/changelog/2026-10-26-gpt-6-1-terra-in-github-copilot)

## Nouveautés

### Salesforce Agent Fabric : coupe-circuit et plafonds de dépenses pour les agents IA

*Statut : accessible · annoncé le 27 octobre 2026*

**Ce que c'est.** Salesforce ajoute à Agent Fabric un Agent Kill Switch (arrêt immédiat d'un agent défaillant), un tableau de bord FinOps avec des plafonds de dépenses imposés (Model Wallet), et des Agent Evals pour détecter automatiquement les baisses de qualité. Des politiques d'optimisation déclarent réduire la consommation de tokens via mise en cache sémantique et compression.

**Pour quoi faire.** Un responsable IA ou un DSI peut configurer des seuils de dépenses qui bloquent les requêtes avant que le budget soit dépassé, et recevoir des alertes automatiques lorsque la qualité d'un agent se dégrade — sans attendre une plainte client.

**Prix.** non précisé par la source

**Limites.** Agent Kill Switch GA maintenant ; Agent Evals en bêta en novembre 2026 ; Triggered-Agent Kill Switch en janvier 2027. La réduction de tokens « jusqu'à 75 % » est basée sur des scénarios de test internes de Salesforce, non garantie en production. Concerne les organisations utilisant la plateforme Salesforce et Agent Fabric.

Sources : [Salesforce — Newsroom](https://www.salesforce.com/news/stories/agent-fabric-catch-failures-control-ai-costs/)

### GitHub Copilot : authentification serveur-à-serveur pour GitHub Apps

*Statut : accès limité · annoncé le 27 octobre 2026*

**Ce que c'est.** GitHub Copilot prend maintenant en charge l'authentification serveur-à-serveur pour les GitHub Apps installées sur des organisations. Les services et agents construits avec le SDK Copilot peuvent effectuer des requêtes au nom de l'organisation sans dépendre des identifiants d'un utilisateur connecté.

**Pour quoi faire.** Pour une agence ou une équipe qui développe des agents ou des pipelines automatisés sur Copilot, cela permet de faire fonctionner ces services de façon continue, sans que leur disponibilité soit liée à un compte utilisateur individuel.

**Prix.** non précisé par la source

**Limites.** Disponible en prévisualisation publique uniquement. Réservé aux GitHub Apps installées sur des organisations. Nécessite l'utilisation du SDK Copilot.

Sources : [GitHub — Changelog](https://github.blog/changelog/2026-10-27-github-copilot-supports-server-to-server-authentication)

## Cas d'usage

### Migrer ses automatisations n8n vers la version 3.0 sans bloquer la production

**Le problème.** n8n 3.0 introduit des breaking changes : certains nœuds, paramètres et packages communautaires peuvent cesser de fonctionner après la mise à jour. Sans préparation, une migration directe risque de bloquer des workflows critiques.

**La démarche.** 1. Consulter la documentation officielle des breaking changes de n8n 3.0 pour repérer les éléments impactés dans vos workflows actuels. 2. Déployer la bêta 3.0 dans un environnement de test distinct de la production. 3. Exécuter les workflows les plus critiques et relever les erreurs ou avertissements. 4. Corriger les nœuds ou configurations obsolètes signalés, workflow par workflow. 5. Planifier la bascule en production avant la sortie de la version stable, prévue début décembre.

**Les outils.** n8n 3.0 bêta (C12 — disponible depuis le 27 octobre 2026)

**L'effort.** Quelques heures pour une structure avec peu de workflows simples ; plus conséquent pour des automatisations complexes ou des packages communautaires personnalisés.

**Le résultat attendu.** Des automatisations migrées sur une base plus stable et sécurisée, les composants obsolètes remplacés, et les fondations prêtes pour les nouvelles fonctionnalités annoncées sur la branche 3.x.

**Limites.** La documentation des breaking changes est en anglais. La version stable n'est pas encore disponible (prévue début décembre selon le blog n8n). Certains packages communautaires peuvent ne pas être compatibles avec la v3 au moment de la bêta.

Sources : [n8n — Blog](https://blog.n8n.io/introducing-n8n-v3/) · [n8n — Releases GitHub](https://github.com/n8n-io/n8n/releases/tag/n8n%403.0.0)

## Le dépôt GitHub

### amontlabs/lcu

**À quoi il sert.** Intégrer la fonctionnalité de computer use de Codex dans ses propres automatisations ou agents, sans passer par l'interface Copilot. Permet de piloter des applications de bureau de façon autonome dans un environnement sur mesure.

**Prérequis.** Node.js ; application ChatGPT Desktop installée localement (obligatoire : elle fournit le moteur d'exécution). La configuration initiale se fait en transmettant les instructions d'installation à un agent.

**Licence.** MIT

**Maintenance.** Projet activement maintenu au moment de la rédaction de cette édition, avec une release v0.13.2 récente — activité et releases consultables directement sur le dépôt.

**Difficulté.** moyenne

**Limites.** Nécessite impérativement l'application ChatGPT Desktop locale. L'installation passe par un processus assisté par agent, ce qui suppose un environnement déjà opérationnel. La documentation d'installation se trouve dans un fichier INSTALLATION.md séparé, non reproduit dans le README principal. Usage expérimental.

Sources : [GitHub](https://github.com/amontlabs/lcu)
